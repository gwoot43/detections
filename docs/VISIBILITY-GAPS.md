# Visibility gaps — domain controller and Active Directory events

One table: the event code (and the field, where the gap is field-level), its classification, the detections that
cannot be made, and an **ES|QL query that proves the gap** rather than asserting it. Each query separates the two
failure modes: no rows means the event is not collected at all, while rows with a zero count in the second
column mean the event arrives but the field or value the detection needs does not.

All queries run against `logs-yourorg-microsoft-windows*` with `winevt.event_data.*`; `winlog.computer_name` is
the event's Computer (not `host.name`). Change the lookback if 30 days is too long for the index.

| Event / field | Type | Detections that cannot be made | Validation (ES|QL) |
|---|---|---|---|
| `5145` — `relative_target_name` | log not collected + field insufficient | Named-pipe method: `psexec`/`atexec`, `\pipe\cert` CA abuse, BloodHound's per-interface RPC. The pipe names - `lsarpc`, `efsr`, `srvsvc`, `samr`, `wkssvc`, `winreg` - were never recorded, so a restored feed alone would not be enough. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "5145" \| STATS events = COUNT(*), last = MAX(@timestamp), named = COUNT(*) WHERE winevt.event_data.relative_target_name IS NOT NULL` |
| `1644` | log not collected | LDAP search: `SDFlags` security-descriptor collection, base-scope vs full-directory walk, the search filter itself. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "1644" \| STATS events = COUNT(*), dcs = COUNT_DISTINCT(winlog.computer_name)` |
| `4662` — `access_mask` `0x10`, `0x100` | field insufficient | DCSync, replication-rights granted, DPAPI backup-key read, gMSA password read, ACL/security-descriptor enumeration. `0x1` arrives, so write-side detections still work. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4662" \| STATS events = COUNT(*), repl_guid = COUNT(*) WHERE winevt.event_data.properties LIKE "*1131f6ad-9c07-11d1-f79f-00c04fc2dcd2*" BY winevt.event_data.access_mask \| SORT events DESC` — the mask list proves nothing is collected at `0x100`; `repl_guid` proves the DCSync rows are absent rather than merely unmasked |
| `4663` | log not collected | File-read on the DC: `ntds.dit`, SAM/SECURITY hives, shadow-copy copy-out. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4663" \| STATS events = COUNT(*), files = COUNT_DISTINCT(winevt.event_data.object_name)` |
| `5136` | **unverified** | Directory modify: DCShadow's DRS SPN add, AdminSDHolder ACL write, SYSVOL/GPO attribute tampering. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "5136" \| STATS events = COUNT(*), system_nc = COUNT(*) WHERE winevt.event_data.object_dn LIKE "*cn=system,*" BY winlog.computer_name` — `system_nc` at zero means AdminSDHolder in particular is unobservable |
| `5137` | **unverified** | Directory object creation: rogue NTDS Settings / server object under `CN=Sites,CN=Configuration`. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "5137" \| STATS events = COUNT(*), sites = COUNT(*) WHERE winevt.event_data.object_dn LIKE "*cn=sites,cn=configuration,*"` |
| `5156` | log not collected | Per-connection attribution on the DC: ADWS-sourced directory access cannot be traced to a client address, because ADWS arrives as `::1`. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "5156" \| STATS events = COUNT(*), apps = COUNT_DISTINCT(winevt.event_data.application)` |
| `4768` | **unverified** | Kerberos AS-REQ: PKINIT certificate logon, pre-auth downgrade, AS-REP roast targeting. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4768" \| STATS events = COUNT(*), with_preauth = COUNT(*) WHERE winevt.event_data.pre_auth_type IS NOT NULL` |
| `4769` | **unverified** | Service tickets: ticket-to-self (UnPAC-the-hash), kerberoasting volume, RC4 downgrade. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4769" \| STATS events = COUNT(*), with_service_sid = COUNT(*) WHERE winevt.event_data.service_sid IS NOT NULL` |
| `39` / `40` / `41` (KDC) | **unverified** | Certificate-mapping failures: another account's SID, no strong mapping, certificate older than the account. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code IN ("39", "40", "41") \| STATS events = COUNT(*) BY winevt.provider_name, event.code` — the provider split matters, because 39-41 are reused by other providers in the System channel |
| `4728` / `4732` / `4756` — membership SID | field insufficient | Tier-0 group grants. The events arrive; the Domain Admins rule matched nothing, so the SID field or its casing is the problem. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code IN ("4728", "4732", "4756") \| STATS events = COUNT(*), sid_present = COUNT(*) WHERE winevt.event_data.target_sid IS NOT NULL, matches_512 = COUNT(*) WHERE TO_UPPER(winevt.event_data.target_sid) LIKE "S-1-5-21-*-512" BY event.code` — `sid_present` at zero is a field-name fault; `matches_512` above zero means the rule's pattern was wrong, not the data |

## Further DC/AD events worth probing

These complete the table above: events the library's DC/AD rules depend on that have **not been probed yet**, so they are marked *to probe* rather than asserted as gaps — they may well be fine. Same two-failure-mode pattern; run each query to confirm or clear it.

| Event / field | Type | Detections at risk | Validation (ES\|QL) |
|---|---|---|---|
| `4738` — `primary_group_id` | to probe (completes `4728`/`4732`/`4756`) | The `primaryGroupID = 512` route in `domain-admins-member-added` — a tier-0 grant that writes no 4728 at all. The main table proves the membership half; this is the other half. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4738" \| STATS events = COUNT(*), with_pgid = COUNT(*) WHERE winevt.event_data.primary_group_id IS NOT NULL` — `with_pgid` at zero means the primary-group route is invisible though the event arrives |
| `4724` | to probe | `computer-account-password-reset` — the silent half of machine-account takeover (RBCD, silver ticket). | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "4724" \| STATS events = COUNT(*), machine_target = COUNT(*) WHERE winevt.event_data.target_user_name LIKE "*$"` — `machine_target` at zero means only user resets are seen |
| `4765` / `4766` / `4794` / `4706` / `4716` | to probe | `trust-sidhistory-dsrm-by-actor` — SID History add/attempt, DSRM password set, trust create/modify. None of the five is in the main table. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code IN ("4765","4766","4794","4706","4716") \| STATS events = COUNT(*) BY event.code` — any code with no rows is a dead branch of that rule |
| `5136` — `msDS-KeyCredentialLink`, `msDS-AllowedToActOnBehalfOfOtherIdentity` | to probe (narrows the `5136` row) | Shadow credentials (KeyCredentialLink) and RBCD — two of the cheapest AD takeover primitives. The main 5136 row proves the event; this proves the two attributes that matter are written. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code == "5136" \| EVAL a = TO_LOWER(TO_STRING(winevt.event_data.attribute_ldap_display_name)) \| STATS events = COUNT(*), shadow_cred = COUNT(*) WHERE a == "msds-keycredentiallink", rbcd = COUNT(*) WHERE a == "msds-allowedtoactonbehalfofotheridentity"` |
| `4776` / `4771` | to probe | NTLM validation (`4776`) for pass-the-hash / NTLM-relay landing on a DC, and Kerberos pre-auth failure (`4771`) for AS-REP roasting and password brute force. | `FROM logs-yourorg-microsoft-windows* \| WHERE @timestamp >= NOW() - 30 days AND event.code IN ("4776","4771") \| STATS events = COUNT(*) BY event.code` |

Out of scope for the two tables above: gaps that are not DC/AD event codes - FDR share names and pipe events, DNS response size, Linux file and audit telemetry, DHCPv6/LLMNR/NBT-NS, and the `winlog.computer_name` vs `host.name` trap - are visibility problems in other sources. The application and WAF feeds that carry their own gaps are the separate table below.

## Other sources

Not DC/AD event codes, so kept separate. Visibility gaps in the application and WAF feeds.

| Source | Gap | Why it matters | How to check |
|---|---|---|---|
| **Confluence search** (Zscaler proxy, `logs-zscaler_zia.web-*`) | Partial coverage — the proxy does not see every search. A good portion of searches run through the **REST API** (`/rest/api/.../search`, CQL), which the proxy does not surface as a search and whose query sits in the request body, not the URL; the rest use the **legacy search-query** URL, whose terms are in the path and so *are* visible. Roughly half the search activity is in the proxy, half is not. | Insider-recon and mass-search / content-staging detections over Confluence (the IN-series) are blind to API-driven search: an actor — or an agent — that enumerates through the API leaves no proxy search trail, and any exfil or search-volume count built on proxy logs undercounts by the API share. | `FROM logs-zscaler_zia.web-* \| WHERE @timestamp >= NOW() - 7 days AND url.domain LIKE "*confluence*" \| STATS total = COUNT(*), legacy_search = COUNT(*) WHERE url.path LIKE "*dosearchsite*" OR url.path LIKE "*searchquery*", api_calls = COUNT(*) WHERE url.path LIKE "*/rest/api/*"` — confirm the path patterns against your own Confluence; the API share is the blind spot, and even those rows don't carry the query (it is in the body) |
| **Imperva Cloud WAF** (`logs-imperva_cloud_waf.event-*`) | `Content-Encoding` is not available in the event feed — the request's content-encoding is not captured or mapped. | Without it you cannot see inbound traffic carrying **`Content-Encoding: br`** (Brotli), and that `br` signal was the thing that mattered: a Brotli-compressed request body can slip past signature inspection — neither the WAF nor the analyst sees the decompressed payload — and `br` on an *inbound* request is itself anomalous, because ordinary browser form posts do not Brotli-encode what they send. With the field absent, both the evasion and the anomaly are invisible, and the payload cannot be reconstructed. | Confirm whether any encoding field is populated: `FROM logs-imperva_cloud_waf.event-* \| WHERE @timestamp >= NOW() - 7 days \| STATS events = COUNT(*), with_encoding = COUNT(*) WHERE <content_encoding_field> IS NOT NULL` — if the field does not exist or `with_encoding` is zero, inbound `br`/`gzip` is invisible; this is a feed mapping/collection gap to raise with the Imperva owner, not an audit switch |
