# Visibility gaps — domain controller and Active Directory events

One table. Each row is a DC/AD event code, the field within it where the gap is field-level, its classification
(**log not collected** / **field insufficient**), the detections that cannot be made, and the switch that fixes
it. Confirmed unless marked **unverified**.

| Event / field | Type | Detections that cannot be made | Remediation |
|---|---|---|---|
| `5145` — `relative_target_name` | log not collected, and field insufficient | Named-pipe method: `psexec`/`atexec`, `\pipe\cert` CA abuse, BloodHound's per-interface RPC. The pipe names themselves - `lsarpc`, `efsr`, `srvsvc`, `samr`, `wkssvc`, `winreg` - were never recorded, so restoring the feed alone would not be enough. | Enable **Detailed File Share** (`auditpol /set /subcategory:"Detailed File Share" /success:enable`) on DCs and file servers, **and** fix the pipeline's `RelativeTargetName` mapping. High volume - scope to the servers that matter. |
| `1644` | log not collected | LDAP search: `SDFlags` security-descriptor collection, base-scope vs full-directory walk, the search filter itself. | Raise NTDS diagnostics to **Level 5**: `HKLM\SYSTEM\CurrentControlSet\Services\NTDS\Diagnostics` → `15 Field Engineering` = `5`. 10-50k EPS on a busy DC - run it as a bounded hunt window, or only on the DCs holding the sensitive objects. |
| `4662` — `access_mask` `0x10`, `0x100` | field insufficient | DCSync, replication-rights granted, DPAPI backup-key read, gMSA password read, ACL and security-descriptor enumeration. The replication rows are control access (`0x100`), which never arrives; `0x1` does, so write-side directory detections still work. | Add a domain-NC SACL entry auditing **Read Property** and **Control Access** on the domain object. One change restores `I01`, `AD02`, `AD04`, `AD09` and the ACL half of the BloodHound rule, and it is cheap compared with Level 5. |
| `4663` | log not collected | File-read on the DC: `ntds.dit`, SAM/SECURITY hives, shadow-copy copy-out - NTDS theft by file rather than by command. | Enable **File System** auditing and add a SACL for `ReadData` on `C:\Windows\NTDS` and the shadow-copy path. Object-level, so it only costs on those files. |
| `5136` | **unverified** | Directory modify: DCShadow's DRS SPN add, AdminSDHolder ACL write, SYSVOL/GPO attribute tampering. | Enable **Directory Service Changes** (`auditpol /set /subcategory:"Directory Service Changes" /success:enable`) and confirm a SACL covers `CN=System` and the configuration partition. |
| `5137` | **unverified** | Directory object creation: rogue NTDS Settings / server object under `CN=Sites,CN=Configuration` - the object half of DCShadow. | Same subcategory as `5136`, plus a SACL on the site container auditing **Create Child**; the default domain-NC SACL does not cover it. |
| `5156` | log not collected | Per-connection attribution on the DC: ADWS-sourced directory access cannot be traced to a client address, because ADWS arrives as `::1`. | Enable **Filtering Platform Connection** (`auditpol /set /subcategory:"Filtering Platform Connection" /success:enable`) - extremely noisy, so scope it to the DCs and the ports of interest, or use Falcon network events as the cheaper substitute. |
| `4768` | **unverified** | Kerberos AS-REQ: PKINIT certificate logon, pre-auth downgrade, AS-REP roast targeting. | Enable **Kerberos Authentication Service** under Account Logon on the DCs - usually on already, since most identity detections depend on it. |
| `4769` | **unverified** | Service tickets: ticket-to-self (UnPAC-the-hash), kerberoasting volume, RC4 downgrade. | Enable **Kerberos Service Ticket Operations** under Account Logon on the DCs. |
| `39` / `40` / `41` (KDC) | **unverified** | Certificate-mapping failures: another account's SID, no strong mapping, certificate older than the account. | No audit policy needed - the KDC writes these to the System channel by default. Fix collection of the System channel and keep the `Kdcsvc` provider filter. |
| `4728` / `4732` / `4756` — membership SID | field insufficient | Tier-0 group membership grants. The events arrive, but the Domain Admins rule matched nothing, so the SID field or its casing is the problem - this is a pipeline fault, not a missing source. | No audit change: confirm `target_sid` is populated, compare `TO_UPPER(...)` against the RID, and add `4738` + `4662` if the grant is done through `primaryGroupID`. |

Out of scope for this table: the gaps that are not DC/AD event codes - FDR share names and pipe events, DNS
response size, Linux file and audit telemetry, DHCPv6/LLMNR/NBT-NS, and the `winlog.computer_name` vs `host.name`
trap - are visibility problems in other sources and are tracked separately.
